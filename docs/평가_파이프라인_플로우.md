## 1. 다이어그램 (텍스트)

### 1.1 일반 채팅 플로우

```
START → handle_request → intent_analyzer → writer → END
```

(가드레일 실패 시 `handle_failure` 등 분기는 `graph.py`·라우터 참고.)

### 1.2 제출 평가 플로우

```
START → handle_request → intent_analyzer
                              |
                    (request_type=SUBMISSION)
                              |
                      eval_turn_guard          [N4]
                              |
                      eval_code_execution      [N5]
                              |
                      eval_static_analysis     [N6]
                              |
                      eval_code_agent          [N7]
                              |
                      holistic_debate          [N8]
                              |
                      aggregate_final_scores   [N9]
                              |
                            END
```

### 1.3 N8 내부 (서브그래프, `subgraph_debate.py`)

```
START
  → Round 1 (병렬): r1_strict | r1_advocate | r1_neutral
  → sync_opinions (팬인)
  → Round 2 (순차): r2_strict → r2_advocate → r2_neutral
  → final_verdict
  → END
```

## 2. 메인 그래프 노드별 Input / Output

LangGraph 노드 ID는 `graph.py` 기준. **N4**의 노드 ID는 `eval_turn_guard`이며, “제출 시 턴 평가를 끝낸 뒤 다음 단계로 넘기는” **게이트(guard)** 의미의 이름이다 (가드레일과 별개).

| 노드 ID | 약칭 | 역할 | Input (주요 State·외부) | Output (주요 State·저장) |
|---------|------|------|-------------------------|---------------------------|
| `handle_request` | N1 | Redis 상태 로드, 턴 처리 | `session_id`, Redis `graph_state:{id}` | `messages`, `current_turn`, `problem_context` 등 갱신 |
| `intent_analyzer` | N2 | CHAT 가드레일·전략 판정 | `messages`, `human_message`, `problem_context`, `request_type` | `intent_status`, `is_guardrail_failed`, `guide_strategy` 등 (분기용 `request_type`은 API 입력 우선) |
| `writer` | N3 | AI 답변 생성 | `messages`, `intent_status`, `problem_context` | `ai_message`, `messages`(append), `writer_status` |
| `eval_turn_guard` | N4 | 제출 시 전 턴 프롬프트 평가 (V3.0) | 메모리 `messages` | `turn_scores`, `aggregate_turn_score` → Redis `turn_logs:{id}:{turn}`, PG `prompt_evaluations` (`TURN_EVAL`) |
| `eval_code_execution` | N5 | Judge0 실행 | `code_content`, `problem_context` | `code_correctness_score`, `code_performance_score`, `test_cases_passed`, `test_cases_total`, `execution_time`, `memory_used_mb`, `correctness_reasoning` |
| `eval_static_analysis` | N6 | Radon CC·AST 등 | `code_content`, `v1_code`, `spec_id` | `code_quality_metrics` (avg_cc, max_cc, delta_cc, ast_pattern_matched, junior_grade 등) |
| `eval_code_agent` | N7 | 단일 LLM 코드 리뷰 | `code_content`, N5·N6 결과, `problem_context` | `code_eval_report` (efficiency/readability/error_handling review, overall_summary, score_adjustment_note) |
| `holistic_debate` | N8 | 다중 에이전트 토론 | Redis `turn_logs:*` 직접 조회 + N4~N7 State 필드 | `holistic_flow_score`, `holistic_flow_analysis`, `r4_context_maintenance_score`, `debate_log`, `debate_initial_opinions`, `debate_rebuttals` |
| `aggregate_final_scores` | N9 | 최종 집계·DB 저장 | 위 점수·메트릭·토론 로그 전반 | `final_scores`, PG `scores` + `rubric_json` |

## 3. N8 서브그래프 — 에이전트별 Input / Output

설정·모델명은 `debate_agents.yaml` 및 `subgraph_debate.py`가 단일 소스. 아래는 구조 요약이다.

| 단계 | 노드 | Input | Output |
|------|------|-------|--------|
| R1 | `r1_strict` | `_build_base_context()`로 만든 전체 컨텍스트 | `AgentOpinion`: score(0~100), reasoning |
| R1 | `r1_advocate` | 동일 | 동일 |
| R1 | `r1_neutral` | 동일 | 동일 |
| — | `sync_opinions` | Round1 세 의견 | `opinions` 리스트 누적 (fan-in) |
| R2 | `r2_strict` | `opinions` + 컨텍스트 | `rebuttal`: score, stance_change, reasoning |
| R2 | `r2_advocate` | 동일 | rebuttal |
| R2 | `r2_neutral` | 동일 | rebuttal |
| — | `final_verdict` | opinions + rebuttals | `FinalVerdict` → holistic 점수·R4·요약 |

## 4. N9 점수 집계 공식 (요약)

구현: `app/domain/langgraph/nodes/eval/n9_final_scores.py`. 세부 조건(통합 점수 `integrated_score` 블렌딩, R4 20% 반영, CC 보너스로 `perf_score` 조정, 등급 `grade` 규칙 등)은 코드와 `점수_계산_로직.md`를 본다.

```
prompt_base = holistic_flow_score × 0.60 + aggregate_turn_score × 0.40
( r4_context_maintenance_score 가 있으면: prompt_score ← prompt_base×0.80 + r4×0.20 )
( integrated_score 가 있으면 추가 블렌딩 — 코드 참고 )

total_score = prompt_score × 0.40
            + code_correctness_score × 0.40
            + code_performance_score × 0.20
```
