# 턴 내용 분해(문제 vs 사용자 요청) 수정 계획

**작성일**: 2026-05-18  
**상태**: 구현 완료 (2026-05-18) — 롤백 시 §4 참고  
**관련 이슈**: 스펙+짧은 코드 요청 턴이 과대 채점됨 (예: `data/3_4_평가.json`, `data/3_5_평가.json`)

---

## 1. 배경

| 현상 | 원인 |
|------|------|
| Turn1에 문제 전문만 붙여도 고점 | 전체 `human_message`를 CREATION 루브릭(R1~R3)으로 채점 |
| Turn2 「코드 짜줘」만 있어도 80점대 | `previous_turns_summary`에 Turn1 스펙 요약 누적 → R2 Context 보정 |
| 3_5 Turn1 스펙+「이거 코드 짜줘」 80점 | 동일 턴 스펙이 R1~R3에 포함 |

**목표**: 문제(스펙) 붙여넣기와 사용자 요청을 분리하고, **다음 턴에는 요청 한줄평만** 넘긴다.

---

## 2. 설계 요약

### 2.1 intent LLM 1회 확장 (`eval_intent_disambiguation.yaml`)

추가 출력 필드:

| 필드 | 값 예 |
|------|--------|
| `problem_in_turn` | `FULL_SPEC` \| `PARTIAL` \| `NONE` |
| `user_request_in_turn` | `NONE` \| `CODE_CREATE` \| `CODE_FIX` \| `EXPLAIN` \| `SETTING` \| `OTHER` |
| `request_one_liner` | 「사용자는 문제에 대한 내용을 제시했습니다.」 |
| `carry_forward` | 「문제 스펙 제시됨. 사용자 요청: 없음」 |

### 2.2 채점 규칙 (현재 vs 변경)

| 패턴 | 예시 | R1~R3 채점 대상 | 현재 | 변경 후 |
|------|------|-----------------|------|---------|
| 스펙만 | 3_4 T1 | 스펙 본문 | 스펙으로 고점 | **동일** (FULL_SPEC + NONE) |
| 스펙+요청 동일 턴 | 3_5 T1 | **요청 구간만** | 스펙+요청 통째 고점 | **요청만**; scoring_cot에 「스펙 참고만, 미반영」 |
| 요청만(이전 스펙) | 3_4 T2 | 요청 본문 | Context로 스펙 보정 | **Context 보정 금지** |

**혼합 턴에서 스펙을 “아예 안 본다”는 뜻이 아님**  
- LLM은 `${text}` 전체를 읽음.  
- **점수에는 스펙 구간을 넣지 않음** (요청 문장/구간만 R1~R3).

### 2.3 다음 턴 요약 (`n4_eval_turn_guard`)

**변경 전**

```text
[Turn 1] 사용자 요약: {human_message 앞 200자…스펙 전체…}
```

**변경 후**

```text
[Turn 1] 사용자: {request_one_liner}
AI 요약: {llm_answer_summary}
```

`user_prompt_summary` = `request_one_liner` (하위 호환).

## 4. 롤백 방법

1. **프롬프트만 되돌리기**: `eval_intent_disambiguation.yaml`, `eval_turn.yaml` git checkout  
2. **코드 되돌리기**: 위 §3 파일 일괄 revert  
3. **DB/Redis**: 신규 필드는 optional — 구 데이터에 영향 없음. 재제출 시 새 규칙 적용.

환경 변수 롤백 스위치는 이번 PR에 넣지 않음 (필요 시 `TURN_CONTENT_DECOMPOSITION_ENABLED=false` 추가 가능).
