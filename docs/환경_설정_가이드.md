## 환경 변수 설정

### 관련 파일

| 경로 | 설명 |
|------|------|
| `.env` | 로컬 개발용 (Git에 포함하지 않음) |
| `.env.prod` | 프로덕션용 (Git에 포함하지 않음) |
| `env.example` | 로컬 환경 예시 (저장소에 포함) |
| `env.prod.example` | 프로덕션 환경 예시 (저장소에 포함) |

### Docker Compose 파일

| 파일 | 용도 |
|------|------|
| `docker-compose.yml` | 기본 (Docker 내부 PostgreSQL 등) |
| `docker-compose.dev.yml` | 로컬 앱 + Docker의 DB·Redis·Adminer (개발) |
| `docker-compose.prod.yml` | 프로덕션 배포용 |

### 환경 변수 우선순위

1. **쉘/시스템 환경 변수** (최우선) — 예: `export POSTGRES_HOST=...`
2. **프로젝트 루트의 `.env`**
3. **코드 기본값** — `app/core/config.py`

### 로컬 `.env` 예시

프로젝트 루트에서 `cp env.example .env` 후 필요한 값을 채웁니다. **`docker-compose.dev.yml`으로 DB·Redis를 띄우는 경우** 호스트에서 접속할 포트는 compose의 포트 매핑과 일치해야 합니다(아래 예는 해당 파일 기준).

```env
GEMINI_API_KEY=your_key_here
POSTGRES_HOST=localhost
POSTGRES_PORT=5435
POSTGRES_DB=ai_vibe_coding_test
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
REDIS_HOST=localhost
REDIS_PORT=6378

# Judge0 (코드 제출 기능 사용 시)
JUDGE0_API_URL=https://judge0-ce.p.rapidapi.com
JUDGE0_API_KEY=your_rapidapi_key_here
JUDGE0_USE_RAPIDAPI=true
JUDGE0_RAPIDAPI_HOST=judge0-ce.p.rapidapi.com
USE_REDIS_QUEUE=true
```

위는 자주 수정하는 항목 위주입니다. 앱 이름·LLM·로컬 Judge0(`JUDGE0_API_URL=http://localhost:2358` 등)까지 포함한 전체 키는 저장소의 `env.example`을 따릅니다.

로컬에 PostgreSQL을 5432 등 다른 포트로 직접 설치해 쓰는 경우에는 `POSTGRES_PORT` 등을 그에 맞게 조정합니다.

### 프로덕션 환경 변수 (예시)

배포 시 환경 변수로 주입하거나 `.env.prod` 등으로 관리할 수 있습니다.

```bash
export POSTGRES_HOST=your-production-db-host.com
export POSTGRES_USER=your_db_user
export POSTGRES_PASSWORD=your_db_password
export POSTGRES_DB=ai_vibe_coding_test
```

배포 실행은 아래 **Docker 명령어** 절의 **프로덕션 배포** 항목을 참고하세요.

## 로컬 개발 환경

### 1. 환경 변수 파일 준비

```bash
cp env.example .env
```

편집기로 `.env`를 열어 DB·Redis·API 키 등을 설정합니다. 개발용 Docker Compose를 쓸 때의 포트는 위 **로컬 `.env` 예시** 절과 `docker-compose.dev.yml`을 함께 확인합니다.

### 2. 인프라 기동 (PostgreSQL · Redis · Adminer)

DB와 캐시는 Docker로 띄우는 것을 권장합니다. 아래 **Docker 명령어** 절의 개발용 Compose 항목에서 `docker-compose -f docker-compose.dev.yml up -d`로 기동합니다.

### 3. Python 환경 (uv)

**uv 설치**

```bash
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# Linux / macOS
curl -LsSf https://astral.sh/uv/install.sh | sh

# 또는 pip
pip install uv
```

**프로젝트 루트에서 의존성 설치**

```bash
# Python 3.10 + 가상 환경 + 의존성 (한 번에)
uv sync

# 의존성만 최신으로
uv sync --upgrade
```

### 4. 애플리케이션 실행

```bash
# 권장: uv run
uv run scripts/run_dev.py

# 또는 uvicorn 직접
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

가상 환경을 직접 켠 뒤 실행할 수도 있습니다.

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```bash
# Linux / macOS
source .venv/bin/activate
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

### 5. Judge0 Worker (코드 제출 기능)

코드 제출 기능을 쓰려면 Worker가 실행 중이어야 합니다.

```bash
uv run python -m app.application.workers.judge_worker
```

## Docker 명령어

### 개발용 (DB · Redis · Adminer)

```bash
# PostgreSQL, Redis, Adminer 기동
docker-compose -f docker-compose.dev.yml up -d

# 컨테이너 목록
docker ps

# 로그 팔로우
docker-compose -f docker-compose.dev.yml logs -f

# 중지
docker-compose -f docker-compose.dev.yml down
```

Redis만 다시 올리거나, 중지된 컨테이너를 켜는 경우:

```bash
docker-compose -f docker-compose.dev.yml up -d redis
docker start ai_vibe_redis_dev
```

### 프로덕션 배포

```bash
docker-compose -f docker-compose.prod.yml up -d
```

(프로덕션 DB 접속 정보는 위 **프로덕션 환경 변수 (예시)** 절 등으로 맞춥니다.)

### Redis 컨테이너에서 확인

```bash
# 컨테이너 내부 redis-cli (권장)
docker exec -it ai_vibe_redis_dev redis-cli

# 연결 테스트
docker exec ai_vibe_redis_dev redis-cli ping

# 로그
docker logs ai_vibe_redis_dev
```

컨테이너 이름이 다른 경우 `docker ps`로 확인한 이름을 사용합니다 (예: `vibecode-redis`).

## 빠른 참조 명령

### Redis CLI — 호스트에서 접속

호스트에 `redis-cli`가 있어야 합니다. **개발 Compose 기본 매핑**이면 호스트 포트는 `6378`입니다.

```bash
redis-cli -h localhost -p 6378
```

Windows에서 컨테이너 이름 확인:

```bash
docker ps | findstr redis
```

### Redis CLI — 자주 쓰는 명령

`redis-cli` 접속 후:

```bash
PING                 # 연결 확인 → PONG
KEYS *               # 모든 키 (운영에서는 KEYS 남용 주의)
KEYS pattern         # 예: KEYS langgraph:*
GET <key>
SET <key> <value>
DEL <key>
DBSIZE
INFO
INFO memory
INFO keyspace
SELECT 0             # DB 0–15
TTL <key>
EXPIRE <key> <sec>
FLUSHDB              # 현재 DB 전체 삭제 (주의)
FLUSHALL             # 모든 DB 삭제 (주의)
```

### macOS: 로컬 Redis와 포트 충돌

맥에 Homebrew 등으로 Redis가 떠 있으면 기본 포트 6379와 충돌할 수 있습니다.

**방법 1 — 로컬 Redis 중지 (권장)**

```bash
brew services list | grep redis
brew services stop redis
# 또는
redis-cli shutdown
```

**방법 2 — Docker Redis 호스트 포트 변경**

`docker-compose.dev.yml`의 `redis.ports`를 예를 들어 `"6380:6379"`로 바꾸고, `.env`의 `REDIS_PORT`도 동일하게 맞춥니다.

**방법 3 — Docker Redis 대신 로컬 Redis만 사용**

`.env` 예:

```env
REDIS_HOST=localhost
REDIS_PORT=6379
```
