## 1. N4 — 턴별 프롬프트 평가 (`aggregate_turn_score`)

### 1.1 턴 점수 (V3.0 루브릭)

각 턴은 의도(intent)에 따라 아래 4개 루브릭 중 적용 가능한 항목만 채점한다.

| 루브릭 | 약칭 | 설명 |
|--------|------|------|
| R1 | Logic & Efficiency | 논리적 완결성 및 효율성 (알고리즘 제약, 최적화 근거) |
| R2 | Clarity & Completeness | 문제 정의의 명확성과 완전성 (정보 누락, 추상적 표현 감점) |
| R3 | Structure & Examples | 구조적 통제 및 예시 활용 (XML 태그, Few-shot 등) |
| R4-local | Context Maintenance (로컬) | 직전 턴 맥락 유지 여부 (N4에서 로컬 판단) |

**의도별 루브릭 적용 매트릭스**

| 의도 | R1 | R2 | R3 | R4-local | turn_score 산식 |
|------|----|----|----|---------|-|
| CREATION | ✅ | ✅ | ✅ | ✅ | avg(R1, R2, R3, R4) |
| SETTING | ✅ | ✅ | ✅ | ✅ | avg(R1, R2, R3, R4) |
| REFINEMENT | ✅ | ✅ | ✅ | ✅ | avg(R1, R2, R3, R4) |
| DEBUGGING | ✅ | ✅ (×2) | ✅ | ✅ | (R1 + R2×2 + R3 + R4) / 5 |
| EXPLORATION | ✅ | ✅ | ❌ | ✅ | avg(R1, R2, R4) |
| FOLLOW_UP | ❌ | ❌ | ❌ | ✅ | R4만 |

**`turn_score`**: 1~5 정수 (V3.0 출력 스키마 `rubric_breakdown` + `applied_rubrics` + `feedback_summary`)

### 1.2 세션 통합 점수

```python
# 모든 턴의 turn_score(1~5) 평균 → 100점 환산
aggregate_turn_score = mean(turn_scores) * 20  # 1~5 → 20~100
```

> 실제 N9에서는 `turn_scores` dict에서 직접 값을 꺼내 평균을 구함.

## 3. N8 — 다중 에이전트 토론 (`holistic_flow_score`)

### 3.1 서브그래프 구조

```
START
  └─ Round 1 (병렬)
       ├── strict    (Gemini 2.5 Pro,  temp 0.1) → opinion(score, reasoning)
       ├── advocate  (Gemini 2.0 Flash, temp 0.3) → opinion(score, reasoning)
       └── neutral   (Gemini 1.5 Pro,  temp 0.2) → opinion(score, reasoning)
  └─ sync_opinions (팬인, opinions 누적)
  └─ Round 2 (순차)
       ├── strict    → rebuttal
       ├── advocate  → rebuttal
       └── neutral   → rebuttal
  └─ final_verdict (Gemini 2.5 Pro, temp 0.0)
       └── holistic_flow_score (0~100)
            r4_context_maintenance_score (0~100)
END
```

### 3.2 에이전트별 역할

| 에이전트 | 모델 | temp | 역할 |
|---------|------|------|------|
| strict | Gemini 2.5 Pro | 0.1 | 프롬프트 결함 집중 비판 |
| advocate | Gemini 2.0 Flash | 0.3 | 사용자 의도·성과 변호 |
| neutral | Gemini 1.5 Pro | 0.2 | 균형 잡힌 중재 |
| verdict | Gemini 2.5 Pro | 0.0 | 토론 종합 → 최종 점수 |

### 3.3 컨텍스트 구성 (`_build_base_context`)

N8 에이전트는 아래 정보를 모두 수신하여 토론에 활용한다:

- N4 Redis `turn_logs`: 대화 원문 요약, `rubric_breakdown`, `applied_rubrics`, `final_reasoning`
- N5: `test_cases_passed/total`, `execution_time`, `memory_used_mb`, `correctness_reasoning`
- N6: `radon_cc.avg_cc`, `radon_cc.max_cc`, `junior_grade`
- N7: `code_eval_report` (efficiency_review, readability_review, error_handling_review, overall_summary)

## 4. N9 — 최종 점수 집계

### 4.1 Prompt Score 계산

```python
# holistic_flow_score: 60%, aggregate_turn_score: 40%
prompt_score = holistic_flow_score * 0.60 + aggregate_turn_score * 0.40
```

### 4.2 최종 Total Score 계산

```python
weights = {
    "prompt":      0.40,   # 프롬프트 활용 (N4 턴 점수 + N8 플로우)
    "correctness": 0.40,   # 코드 정확성 (N5 Judge0)
    "performance": 0.20,   # 코드 성능 (N5 Judge0)
}

total_score = (
    prompt_score           * 0.40 +
    code_correctness_score * 0.40 +
    code_performance_score * 0.20
)
```

**최종 가중치 요약**

| 항목 | 가중치 | 구성 |
|------|--------|------|
| Prompt Score | **40%** | N8 holistic_flow(60%) + N4 aggregate_turn(40%) |
| Correctness Score | **40%** | N5 Judge0 통과율 |
| Performance Score | **20%** | N5 Judge0 시간·메모리 |

> ⚠️ 이전 구성(Correctness 30%, Performance 30%)에서 변경됨.  
> Correctness 비중이 40%로 상향, Performance가 20%로 축소.

## 5. 점수 계산 예시

### 실제 Flow 예시

```
holistic_flow_score   = 88.0  (N8 다중 토론 결과)
aggregate_turn_score  = 85.0  (N4 V3.0 루브릭 평균)
code_correctness_score = 100.0 (N5 Judge0 100% 통과)
code_performance_score = 100.0 (N5 Judge0 성능)

1. Prompt Score 계산:
   prompt_score = 88.0 * 0.60 + 85.0 * 0.40 = 52.8 + 34.0 = 86.8

2. Total Score 계산:
   total_score = 86.8 * 0.40 + 100.0 * 0.40 + 100.0 * 0.20
               = 34.72 + 40.0 + 20.0
               = 94.72점
```

> 이 예시는 실제 `data/17_7_평가.json` 데이터 기준 (exam 17, session 7, TSP).

## 6. 테스트 스크립트 (Judge0만 평가 시)

Judge0만 테스트할 때 Prompt Score가 없으므로:

```python
# Judge0 단독 테스트 (Prompt Score 제외)
total_score = correctness_score * 0.50 + performance_score * 0.50
```

또는 Prompt Score를 0으로 포함할 경우:

```python
total_score = 0 * 0.40 + correctness_score * 0.40 + performance_score * 0.20
```
