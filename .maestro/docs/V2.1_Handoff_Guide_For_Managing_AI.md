# v2.1 작업 위임 마스터 가이드 (전체 관리 담당 AI용)

> **대상**: v2.1 개편 작업을 **총괄하는 관리 AI**.  
> 직접 구현하지 않고, **다른 AI에게 단계별로 지시문을 전달**해 순차 진행시키는 방법을 정리한 문서입니다.  
> **핵심 원칙**: 텍스트 제출 형식을 유지하되, 내부적으로 **v1(초기) / v2(최종) 코드**를 정밀 비교하여 **A~F 등급**을 산출하고 **파인튜닝 데이터**를 추출한다.

---

## 1. 개편 핵심 기술 명세 (Technical Baseline)

구현 시 모든 Step이 아래 명세를 따르도록 한다.

| 항목 | 명세 |
|------|------|
| **제출 방식** | 텍스트 기반 유지. 내부적으로 **v1_code**, **v2_code** 스냅샷을 관리한다. |
| **평가 지표** | **Radon CC**: 복잡도 상승률(ΔCC) 및 함수당 평균 복잡도 측정. **AST 패턴**: 클래스 상속 및 전략 패턴 구현 여부 물리적 검증. |
| **DB 연동** | **prompt_evaluations** 테이블의 **details (JSONB)** 필드에 모든 수치 및 등급을 저장한다. |
| **등급 체계** | **A**(Senior), **B**(Mid), **C**(Junior), **D**(Beginner), **F**(Fail). |

---

### 1.1 8대 의도 → 4대 통합 의도 매핑 (공식)

Step 02 구현 및 평가 시 아래 표를 **준거**로 사용한다. 기존 8가지 분류를 4대로 통합할 때만 이 매핑을 적용한다.

| 기존 의도 (Original) | 통합 의도 (Unified) | 매핑 사유 및 평가 초점 |
|----------------------|---------------------|-------------------------|
| SYSTEM_PROMPT | 1. 설계 판 짜기 (SETTING) | AI에게 페르소나를 부여하고 전체적인 아키텍처 규칙과 제약 조건을 설정하는 초기 빌드업 단계입니다. |
| RULE_SETTING | 1. 설계 판 짜기 (SETTING) | (동일: 설계·규칙 설정) |
| GENERATION | 2. 기능 만들기 (CREATION) | 실제 비즈니스 로직을 코드로 구현하도록 지시하는 단계입니다. 시나리오에 따른 기능 추가가 핵심입니다. |
| FOLLOW_UP | 2. 기능 만들기 (CREATION) | (동일: 기능 구현·추가 지시) |
| OPTIMIZATION | 3. 코드 다듬기 (REFINEMENT) | 이미 작성된 코드의 구조를 개선(리팩토링)하거나 버그를 잡는 단계로, 시니어급 역량이 가장 많이 드러납니다. |
| DEBUGGING | 3. 코드 다듬기 (REFINEMENT) | (동일: 리팩토링·버그 수정) |
| TEST_CASE | 4. 검증하기 (VALIDATION) | 구현된 로직이 엣지 케이스에서 잘 돌아가는지 확인하고 AI에게 검증을 요청하는 단계입니다. |
| HINT_OR_QUERY | 4. 검증하기 (VALIDATION) | (동일: 검증·테스트 요청) |

## 3. 진행 순서 및 상세 지시문 (Steps)

**반드시 아래 순서를 따른다.**

| 순서 | Step | 선행 조건 |
|------|------|-----------|
| 1 | Step 01 | 없음 |
| 2 | Step 02 | Step 01 완료 |
| 3 | Step 03 | Step 01 완료 |
| 4 | Step 04 | Step 01 완료 |
| 5 | Step 05 | Step 01 + Step 04 완료 |
| 6 | Step 06 | Step 04 완료 |

- Step 02와 Step 03은 서로 의존하지 않으므로 순서를 바꿔도 됨 (둘 다 Step 01 이후).
- Step 05는 Step 04 완료 후에만 진행.

---

### Step 01: 도메인 모델 및 상태 객체 확장 + Snapshot 아키텍처

- **지시문**: `.maestro/docs/V2.1_Step_01_Problem_And_State.md`
- **상세 명세**:
  - **MainGraphState**에 `v1_code`, `v2_code`(텍스트), `v1_metrics`, `v2_metrics`(Dict/JSONB) 필드 추가.
  - **Snapshot 정의**: v1_code = Phase 1 구현 후 SAVE로 확정된 Baseline 코드. v2_code = 최종 제출 시점의 Final 코드.
  - **Enum 정의** (String 기반): **GradeType**(A,B,C,D,F), **UnifiedIntentType**(SETTING, CREATION, REFINEMENT, VALIDATION), **RubricType**(SPECIFICITY, DESIGN_CONTROL, ROBUSTNESS, CONSISTENCY, EFFICIENCY).
  - **Snapshot 저장**: 프론트 SAVE 요청 시 `prompt_messages.meta`(JSONB)에 `{ "code_snapshot": "코드전체", "is_v1_checkpoint": true }` 포함되도록 설계. (api/chat/save-message 또는 전용 save 엔드포인트 대응.) 이 meta가 Step 04에서 v1_code를 찾는 유일한 추적 단서.
  - **problem_info**: '스마트 게이트 2026' 시나리오 추가 (Phase 1: 기본 보안·수하물 과금 / Phase 2: 긴급 보안 등급 HIGH, 누적 과금 페널티).
  - **제약**: 모든 데이터는 최종적으로 prompt_evaluations.details(JSONB)에 통합 저장 가능한 구조. 코드는 str로 관리, DB 저장 시에만 JSON 직렬화.
- **완료 보고**: v1_code가 prompt_messages.meta에 기록되는 **예시 JSON 구조**와 **수정한 파일 목록**을 반드시 보고.

---

### Step 02: 통합 의도 분석기 (Node 4)

- **지시문**: `.maestro/docs/V2.1_Step_02_Intent_Analyzer.md`
- **상세 명세**:
  - 턴별 **8가지 의도 → 4대 통합 의도** 매핑 로직 구현. **매핑 규칙은 §1.1 표를 반드시 사용** (SYSTEM_PROMPT/RULE_SETTING→SETTING, GENERATION/FOLLOW_UP→CREATION, OPTIMIZATION/DEBUGGING→REFINEMENT, TEST_CASE/HINT_OR_QUERY→VALIDATION).
  - 매핑 결과와 턴 정보를 **prompt_evaluations.details["unified_intent"]**에 저장할 수 있도록 상태 갱신.

---

### Step 03: 전략적 Writer 분기 로직 (Node 3)

- **지시문**: `.maestro/docs/V2.1_Step_03_Writer.md`
- **상세 명세**:
  - **Steering Test**: `human_message`에서 아키텍처 용어(Pattern, Interface, OCP 등) 감지 로직 추가.
  - **분기**: 용어 미사용 시 의도적으로 **스파게티 코드** 생성, 용어 사용 시 **클린 코드** 생성으로 수험자의 리팩토링 능력 유도.

---

### Step 04: 통합 평가 엔진 (Node 6b - Integrated Evaluator)

- **지시문**: `.maestro/docs/V2.1_Step_04_Integrated_Evaluator.md`
- **상세 명세 (임계치 적용)**:
  - **v1_code 대비 v2_code의 ΔCC** 산출.
  - **AST 검사**: SecurityRule 상속 및 GateManager의 전략 패턴 구조 유지 확인.
  - 모든 분석 데이터(CC 수치, 패턴 탐지 결과)를 **details["code_quality_metrics"]**에 기록.

---

### Step 05: 최종 학점 집계 및 리포트 (Node 7)

- **지시문**: `.maestro/docs/V2.1_Step_05_Graph_And_Scores.md`
- **등급 임계치 (Hard-coded)**:
  - **A**: ΔCC ≤ 10% & 평균 CC < 5 & AST 패턴 매칭 성공.
  - **B**: ΔCC ≤ 30% & 평균 CC < 8.
  - **C**: ΔCC ≤ 60% & 평균 CC < 12.
  - **D/F**: 기준 미달 또는 기능 오류.
- **결과**: 점수 및 Grade를 **scores** 테이블과 **rubric_json**에 최종 반영.

---

### Step 06: 파인튜닝 데이터 추출 파이프라인

- **지시문**: `.maestro/docs/V2.1_Step_06_Finetuning_Data.md`
- **상세 명세**:
  - **PostgreSQL**의 `prompt_messages`와 `prompt_evaluations`를 결합하여 **(사용자 프롬프트) + (코드 수치 변화) → (Grade)** 세트를 **JSONL**로 추출하는 스크립트 작성.

## 4. 다른 AI에게 작업 지시할 때 (한 번에 한 Step만)

### 4.1 전달 원칙

1. **역할**: "v2.1 Step N 구현을 맡는다."
2. **지시문**: 해당 Step 문서 경로 + **본 가이드 §3의 해당 Step 상세 명세**를 함께 전달한다.
3. **제약**: Technical Baseline(§1) 및 등급·DB 저장 방식 준수. 선행 Step은 반영된 상태로 가정하고, 해당 Step만 수정할 것.
