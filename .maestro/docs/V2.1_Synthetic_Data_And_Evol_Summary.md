# v2.1 합성 데이터·Evol-Instruct 작업 요약

> **작성 목적**: Step 01~06 이후 진행한 **합성 데이터 생성**, **평가 루브릭 연동 데이터셋**, **Evol-Instruct 적용**까지의 내용을 Maestro에 기록.  
> **파인튜닝용 데이터 증강**은 별도 AI에서 진행 예정이므로, 본 문서는 “여기까지 한 것”과 “다음 담당이 할 것” 경계만 명시한다.

## 1. 요약

| 구분 | 내용 |
|------|------|
| **합성 데이터** | 등급별(A~F) 프롬프트·코드·메트릭을 스크립트/Gemini로 생성. `v21_rubric_60.jsonl`(60건), `v21_final_synthetic_dataset.jsonl` 등. |

| **파인튜닝 증강** | **다른 AI에서 진행 예정.** 본 레포에서 준비한 Seed/진화 데이터·스키마를 활용해 증강 파이프라인을 이어가면 됨. |

## 2. 합성 데이터 (등급별 Seed)

### 2.1 스크립트

- **`scripts/generate_synthetic_v21_data.py`**
  - A~F 등급별 **instruction 변형** 여러 종(등급당 6종) 정의 → 같은 등급이라도 12건이 서로 다른 프롬프트가 되도록 구성.
  - **Seed**: 등급별 기본 프롬프트(스마트 게이트 2026). F는 의도적 오해(REJECT 지시) + 잘못된 코드 포함.

### 2.2 출력 데이터

- **`v21_rubric_60.jsonl`** (프로젝트 루트 또는 `-o` 지정 경로)
  - 60건 = 등급당 12건. **행마다 다른 instruction** (6종 변형 × 2회).
  - 필드: `instruction`, `instruction_phase2`, `context`, `v2_code`, `metrics`, `label`, `analysis_reasoning`, `evaluation_log`.

### 2.3 루브릭 수치·평가 사유

- **metrics**: `delta_cc_pct`, `clarity`, `problem_relevance`, `rules`, `examples`, `context` (0~100), `ast_pattern_matched`, `has_v1`, `junior_grade` 등.
- **analysis_reasoning**: 평가자 관점 한 줄 요약 (예: "아키텍처 용어 미사용으로 설계 지침 부족(B등급 사유)").
- **evaluation_log**: 상세 평가 사유(명확성·문제 적절성·규칙 등 점수와 설명). **AI가 스스로 평가 사유를 작성하는 학습용**으로 사용 예정.

### 2.4 실행 예

```bash
# 60건 생성 (등급별 변형, API 없이 폴백)
uv run python scripts/generate_synthetic_v21_data.py --no-gemini -o v21_rubric_60.jsonl
```

## 3. Evol-Instruct (5단계 진화 + 평가 노드)

### 3.1 스크립트

- **`scripts/evol_instruction_v21.py`**
  - **Seed**: `v21_rubric_60.jsonl`(또는 `--input`으로 지정한 JSONL)의 각 행.
  - **5단계 진화** (Seed당 랜덤 1종):
    1. **add_constraints**: 시간 복잡도, 외부 라이브러리 미사용 등 제약 추가.
    2. **deepening**: Interface 상속·전략 패턴 등 아키텍처 깊이 심화.
    3. **complicating_input**: 입력 구조 복잡화(리스트·중첩 등).
    4. **reasoning_step**: “왜 그렇게 설계해야 하는지” 논리적 근거 포함 지시.
    5. **situation_switching**: 공항 → 병원/은행 등 도메인 변경.
  - LLM(Gemini) 사용 가능 시 위 5종을 LLM으로 진화; 불가 시 **템플릿 폴백**으로 동일 5종 변형 생성.

### 3.2 평가 노드 순회

- **`--run-eval`** 옵션 시: 진화된 프롬프트를 **Eval Turn SubGraph**에 넣어 다음을 추출.
  - `eval_turn_score`, `eval_intent_types`, `eval_intent_confidence`, `eval_rubrics`, `eval_reasoning`.
- **ΔCC, AST** 등 코드 품질 지표는 **전체 제출 플로우**(DB 세션 + `EvalService.submit_code`)에서만 산출. 진화된 JSONL을 DB에 넣은 뒤 `run_synthetic_session_eval.py`로 실행하면 됨.

### 3.3 실행 예

```bash
# 진화만 (60건)
uv run python scripts/evol_instruction_v21.py --input v21_rubric_60.jsonl -o v21_evol.jsonl

# 진화 + Eval Turn SubGraph로 reasoning 추출 (예: 10건)
uv run python scripts/evol_instruction_v21.py -i v21_rubric_60.jsonl -o v21_evol.jsonl --run-eval --max-samples 10
```

## 5. 파인튜닝용 데이터 증강 (다른 AI 진행)

- **파인튜닝용 데이터 증강**은 **다른 AI에서 진행**한다.
- 본 레포에서 준비된 것:
  - **Seed/진화 데이터**: `v21_rubric_60.jsonl`, `v21_evol.jsonl`(및 동일 스키마 JSONL).
  - **스키마**: instruction, context, v2_code, metrics, label, analysis_reasoning, evaluation_log, (선택) eval_* 필드.
  - **Evol-Instruct 스크립트**: Seed → 5종 진화 → (선택) Eval Turn reasoning 추출까지 한 번에 실행 가능.
- 다음 담당 AI는 위 데이터·스크립트를 기반으로 **증강 파이프라인**(추가 변형, 필터링, 포맷 변환 등)을 이어가면 된다.
