# v2.1 Step 06: 파인튜닝 데이터 수집 스크립트

> **대상**: (수정 프롬프트, 코드 CC 변화, AST 패턴 일치 여부) 데이터 페어를 수집하는 스크립트/파이프라인.  
> **선행 조건**: Step 04 완료 (Radon CC·AST 패턴 계산 및 저장 구조 확립).

**기준**: `.maestro/docs/V2.1_Work_Instructions.md` §5

---

## 1. 목표

- **데이터 페어**: `(수정 프롬프트, 코드의 CC 변화, AST 패턴 일치 여부)` 수집.
- **학습 목표**: 사용자가 **구조적 용어**로 AI를 통제했을 때 **코드 복잡도가 낮아지는 현상**을 모델이 고득점으로 인식하도록 하는 학습 데이터 구성.

---

## 2. 수집 항목

| 필드 | 설명 |
|------|------|
| `modification_prompt` | 사용자가 2차 수정을 요청한 텍스트 (예: "2차 요구사항 반영해줘" vs "규칙 인터페이스 상속받아 SecurityRule 추가해줘") |
| `cc_before` | 수정 전 함수별 Cyclomatic Complexity (또는 max CC) |
| `cc_after` | 수정 후 함수별 Cyclomatic Complexity (또는 max CC) |
| `ast_pattern_matched` | SecurityRule 상속 여부, GateManager 전략 패턴 여부 (boolean 또는 세부 플래그) |
| `label` / `score` | 고득점·저득점 (파인튜닝 타깃) |

---

## 3. 수정·추가 파일

| 위치 | 작업 내용 |
|------|------------|
| `scripts/` 또는 `.maestro/scripts/` | 세션/제출 로그 또는 DB에서 대화·제출 코드를 읽어, 턴별로 수정 프롬프트·제출 코드 추출. Step 04에서 저장한 code_quality_metrics(radon_cc 등)·AST 결과와 매칭하여 한 줄씩 JSON/JSONL 생성. |
| 출력 경로 | `.maestro/data/finetuning/phase6_gemma/` 또는 동일 목적 디렉터리. 파일명 예: `v21_cc_ast_pairs.jsonl`. |

---

## 4. 데이터 소스

- **수정 프롬프트**: prompt_messages 또는 Redis/State에서 턴 N의 human_message (2차 요구사항 반영 요청 턴).
- **코드**: 해당 턴 이후 제출 코드 또는 턴별 AI 응답에서 추출한 코드.
- **CC/AST**: Step 04에서 제출 시 이미 계산·저장한 `code_quality_metrics` 활용. 또는 스크립트 내에서 Radon·AST 유틸을 직접 호출해 계산.
