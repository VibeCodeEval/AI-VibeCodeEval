# v2.1 Step 02: 제출 시 턴별 평가에서 4대 통합 의도 (Node 4 · Eval Turn)

> **대상**: **Node 4 (Eval Turn Guard + Eval Turn SubGraph)**. 제출 시 각 턴을 평가할 때, 기존 **8가지 의도** 분류 결과를 **4대 통합 의도**로 매핑하여 저장·하위 노드에서 사용.  
> **참고**: 의도 분류는 **채팅 시 Node 2(Intent Analyzer)**가 아니라 **제출 시 Node 4(Eval Turn)의 intent_analysis**에서 이루어집니다. v2.1에서 4대 의도는 이 평가 단계에서만 도입하면 됩니다.  
> **선행 조건**: Step 01 완료 (UnifiedIntentType, State/저장 구조 정의).

**기준**: `.maestro/docs/V2.1_Work_Instructions.md` §4.1

---

## 1. 목표

- **현재**: 제출 시 Eval Turn SubGraph의 `intent_analysis`에서 턴별로 **8가지 CodeIntentType** 분류 → intent_router → eval_* 노드들.
- **v2.1**: 8가지 분류 결과를 **4대 통합 의도**(Setting / Creation / Refinement / Validation)로 **매핑**하여, 턴 로그·turn_analysis 또는 DB 메타에 `unified_intent`로 저장. 이후 Integrated Evaluator(Step 04)나 최종 점수에서 4대 의도 기준 집계·루브릭에 활용.

**4대 통합 의도**:

| 의도 | 설명 |
|------|------|
| SETTING (설계 판 짜기) | AI 페르소나·초기 아키텍처 방향 설정 |
| CREATION (기능 만들기) | 1/2차 비즈니스 로직 구현 지시 |
| REFINEMENT (코드 다듬기) | 리팩토링·패턴 적용 지시 |
| VALIDATION (검증하기) | 엣지 케이스·테스트 요청 |

---

## 2. 8대 → 4대 매핑 표 (공식)

구현 시 **아래 표만** 사용한다. 기존 8가지(CodeIntentType) 분류 결과를 이 표 기준으로 4대 통합 의도로 매핑한다.

| 기존 의도 (Original) | 통합 의도 (Unified) | 매핑 사유 및 평가 초점 |
|----------------------|---------------------|-------------------------|
| SYSTEM_PROMPT | 1. 설계 판 짜기 (SETTING) | AI에게 페르소나를 부여하고 전체적인 아키텍처 규칙과 제약 조건을 설정하는 초기 빌드업 단계입니다. |
| RULE_SETTING | 1. 설계 판 짜기 (SETTING) | (동일: 설계·규칙 설정) |
| GENERATION | 2. 기능 만들기 (CREATION) | 실제 비즈니스 로직을 코드로 구현하도록 지시하는 단계입니다. 시나리오에 따른 기능 추가가 핵심입니다. |
| FOLLOW_UP | 2. 기능 만들기 (CREATION) | (동일: 기능 구현·추가 지시) |
| OPTIMIZATION | 3. 코드 다듬기 (REFINEMENT) | 이미 작성된 코드의 구조를 개선(리팩토링)하거나 버그를 잡는 단계로, 시니어급 역량이 가장 많이 드러납니다. |
| DEBUGGING | 3. 코드 다듬기 (REFINEMENT) | (동일: 리팩토링·버그 수정) |
| TEST_CASE | 4. 검증하기 (VALIDATION) | 구현된 로직이 엣지 케이스에서 잘 돌아가는지 확인하고 AI에게 검증을 요청하는 단계입니다. |
| HINT_OR_QUERY | 4. 검증하기 (VALIDATION) | (동일: 검증·테스트 요청) |

## 3. 수정 파일

| 파일 | 작업 내용 |
|------|------------|
| `app/domain/langgraph/nodes/turn_evaluator/analysis.py` | `intent_analysis` 결과(8가지 intent_types)에 대해 **8→4 매핑** 함수 적용, 반환 State에 `unified_intent`(UnifiedIntentType 값) 추가. |
| `app/domain/langgraph/nodes/turn_evaluator/aggregation.py` (또는 turn_log 저장 위치) | 턴 로그·turn_log에 `unified_intent` 포함되도록 전달. |
| `app/domain/langgraph/states.py` | EvalTurnState에 `unified_intent: Optional[str]` 필드 추가 (없을 경우). |
| DB 저장 (eval_service / session_repository 등) | 제출 시 턴별 메타에 `unified_intent` 저장해 두면, Step 04 Integrated Evaluator에서 조회 가능. |

---

복수 의도가 나온 턴은 **위 §2 표에서 첫 번째로 매칭되는 기존 의도**를 기준으로 통합 의도를 정하거나, 우선순위(SETTING > CREATION > REFINEMENT > VALIDATION 등)를 정해 턴당 `unified_intent` 하나를 선택한다. 기존 `intent_types`(8가지)는 보조로 유지해도 된다.

## 4. 입출력·의존성

- **입력**: 기존 EvalTurnState (human_message, ai_message, turn 등). Step 01에서 정의한 `UnifiedIntentType` import.
- **출력**: `intent_analysis` 반환값에 `unified_intent` 포함. 이후 aggregate_turn_log·DB 저장 시 함께 저장.
