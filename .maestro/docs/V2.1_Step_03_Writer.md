# v2.1 Step 03: Writer LLM (Node 3) – 조건부 응답 (클린 vs 스파게티)

> **대상**: Node 3 Writer. 사용자 지시가 **구조적 용어**인지 **모호한 지시**인지에 따라 **클린 아키텍처** vs **복잡도 높은(스파게티)** 코드 응답으로 분기.  
> **선행 조건**: Step 01 완료 (스마트 게이트 2026 문제·키워드 정의).

**기준**: `.maestro/docs/V2.1_Work_Instructions.md` §3.1

---

## 1. 목표

- **모호한 지시** (예: "2차 요구사항 반영해줘"): `check_passenger` 등 한 함수에 로직을 몰아 넣은 **복잡도 높은 코드**를 제공 → 리팩토링 지시 유도.
- **구조적 지시** (예: "기존 규칙 인터페이스를 상속받아 SecurityRule을 추가해줘"): **클린 아키텍처** 응답 (규칙 인터페이스·전략 패턴 유지, SecurityRule이 BaseRule 상속).

---

## 2. 수정 파일

| 파일 | 작업 내용 |
|------|------------|
| `app/domain/langgraph/nodes/writer.py` | 사용자 메시지에서 **구조적 용어** 감지 로직 추가. 감지 시 "클린" 시스템 프롬프트/지시 사용, 미감지 시 "스파게티" 유도 프롬프트 사용. (문제가 스마트 게이트 2026일 때만 적용할지, 전역 적용할지 규칙 명시) |
| Writer용 프롬프트 YAML 또는 문자열 | (1) 클린 아키텍처용: BaseRule 인터페이스, SecurityRule 상속, GateManager 전략 패턴 유지 지시. (2) 스파게티 유도용: 한 함수에 조건 몰아넣기 유도 지시. |
| `app/domain/langgraph/utils/problem_info.py` | 스마트 게이트 2026용 **클린 예시 코드**·**스파게티 예시 코드** 스니펫이 있으면 problem_context에서 참조 가능하게 (선택). |

---

## 3. 구조적 용어 (감지 키워드/패턴)

다음과 같은 표현이 포함되면 **구조적 지시**로 분기:

- "규칙 인터페이스", "인터페이스 상속", "BaseRule", "SecurityRule", "전략 패턴", "Strategy"
- "상속받아", "확장해서", "패턴으로", "분리해서", "Rule로"

이외 또는 짧은 "반영해줘", "수정해줘"만 있으면 **모호한 지시**로 분기.

---

## 4. 입출력·의존성

- **입력**: `state["human_message"]`, `state["problem_context"]`, `state.get("spec_id")`. Step 01에서 정의한 스마트 게이트 2026 `spec_id`로 해당 문제 여부 판단 가능.
- **출력**: 기존과 동일하게 AI 응답 메시지. 내부적으로 사용하는 시스템 프롬프트만 분기.
